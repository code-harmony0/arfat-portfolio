Problems from production, and what I did.

Mostly from Zonesso. Each one is a symptom, a cause and a fix I can walk you through.

ProblemWhat brokeWhat I did

Google's 16 KB rule for Android appsAndroid

Google would have stopped accepting updates to the app. Play now requires apps to run on newer phones that handle memory in 16 KB blocks. Native code built for 4 KB blocks can fail on those phones.

Updated the app's build tools so it meets the rule. Moved the Android build to NDK 28 and target SDK 36 so the native code the app ships is compliant.

People signed out when their connection droppedChat and sign-in

A dropped connection or a switch to another app logged people out of their account. The chat socket's disconnect handler was changing login state.

Made sign-in change only when a person logs in or out. A disconnect is a network event, not a sign-out, so login state now changes only in the login and clear-data flows.

Apple refused to publish an updateiOS

Apple's review rejected a build. It flagged two things: how the app asks permission to track people, and how easy in-app purchases were to find. The rules are App Tracking Transparency and in-app-purchase discoverability.

Fixed both issues, as the review required. Brought the tracking-permission handling into compliance and made purchases discoverable in the app.

Paying inside the iPhone app broke on iOS 18Payments

After iOS 18, in-app purchases stopped working. The payment library did not handle the new iOS version.

Upgraded and patched the payment library so purchases work again. Upgraded react-native-iap to v13, patched it for iOS 18 and fixed the account token to be a UUID.

Notification taps landed on the wrong screenPush

Tapping a notification while the app was still starting could send people to the wrong place. The tap arrived before the app was ready to navigate.

Made the app wait, then open the right screen. Added deep-link retry, so a tap during a cold launch still lands on the right screen.

Samsung Pay failing in the released appAndroid

Samsung Pay could stop working in the released app, even though it worked while testing. Release builds trim unused code, which can strip what the SDK needs.

Told the build tool to keep the Samsung Pay code. Wrote explicit ProGuard keep rules for the Samsung Pay SDK so it survives release shrinking.

The brief

A Dubai vehicle marketplace needed a mobile app people could browse, post and pay in. I became its only mobile engineer, so architecture, payments, testing and every release sat with me.

How I approached it

Listings, posting an ad and checkout decide a marketplace, so I put structure around those three first. Server state moved to TanStack Query and app state to Jotai. Five payment methods went behind one checkout.

What shipped

A live iOS and Android app, a React Native upgrade run as a cleanup, a CI-tested release pipeline, and a scope that has grown to the Next.js site and admin dashboard.
